# Terived TH41-3 switching with kvmctl

## Protocol

Sequential hotkey grammar (from the official manual): **Right Ctrl tapped
twice → port number → Enter**. Every key is fully released before the next is
pressed; the switch's hotkey engine does not recognize simultaneous chords.

Implemented in `kvmctl/switch.py`:

- `TH41_3` profile (`terived-th41-3`), ports 1–4.
- `plan_switch(profile, port)` validates the port and returns the exact event plan.
- `execute_switch(client, TH41_3, port, dry_run=..., inter_key_delay=..., settle_delay=...)`
  emits discrete down/up events with configurable inter-key delay (default 0.2 s)
  and post-sequence settle delay (default 1.0 s). `dry_run=True` sends nothing.

### Held-key mode (verified recipe)

Plain taps are filtered by the switch's hotkey detector. The repeatable recipe
uses **held keys**: each key is held down for 120 ms, then released, with a
150 ms gap before the next key. Enable it via `hold_ms` on a profile:

    from kvmctl.switch import SwitchProfile, execute_switch

    TH41_3_HELD = SwitchProfile(
        name="terived-th41-3-held", min_port=1, max_port=4,
        sequence=(("ControlRight", "tap"), ("ControlRight", "tap"),
                  ("Digit{port}", "tap"), ("Enter", "tap")),
        hold_ms=0.120,          # verified hold duration
        inter_key_delay=0.150,  # verified inter-key gap
    )
    execute_switch(client, TH41_3_HELD, 2)

Held-key execution remains strictly sequential — no two keys are ever held at
once — preserving the protocol invariant.

## Full select cycle (`kvmctl.machines`)

`select_machine(client, session, name)` implements the whole resolved recipe:

1. Optional OTG re-arm: bounce `/api/system/otg_functions`
   `start_cdrom=true&start_flash=true`, wait 8 s, then both false, wait 12 s.
   The USB re-enumeration arms the hotkey engine. Also available standalone as
   `rearm_otg(client)` in `kvmctl.switch`.
2. Held-key sequence `ControlRight x2, Digit<N>, Enter` (120 ms hold / 150 ms gap).
3. Settle ~5 s, then verify per policy (`FRAME_CHANGE`, `OCR_IDENTITY`,
   `PROMPT_PATTERN`) against the rack profiles in `RACK`.

Selection state is explicit (`UNKNOWN → SELECTED_UNVERIFIED → VERIFIED |
VERIFY_FAILED`) on `SessionState`; failures never leave a silently-trusted
record. Safe failure: an OTG bounce failure raises before any keystrokes leak
to the console.

## Streamer recovery (`kvmctl.recovery`)

The OTG bounce kills the ustreamer. `recover_streamer(client, open_ws=...)`:

- tolerates exactly the expected first-snapshot HTTP 503,
- nudges the encoder via `/api/streamer/set_params?desired_fps=40&quality=80`,
- retries snapshots until one succeeds,
- opens a fresh stream WebSocket at `/api/ws?stream=1` through the injected
  `open_ws` callable (the WS must be held open to keep ustreamer alive).

Example:

    from kvmctl.recovery import recover_streamer
    recover_streamer(client, open_ws=my_websocket_opener)

Example:

    from kvmctl.switch import TH41_3, execute_switch
    execute_switch(client, TH41_3, 2)                    # live
    execute_switch(client, TH41_3, 2, dry_run=True)      # plan only

## Wiring requirements (empirically required)

1. **Comet storage gadget must be disabled** (`start_cdrom=false`,
   `start_flash=false`). With storage active, hotkeys never work — USB mass-
   storage enumeration takes the keyboard path and the switch's hotkey engine
   disengages.
2. **The Comet's USB cable must terminate in the TH41-3 port marked with the
   KEYBOARD icon** (the dedicated hotkey port). Hotkeys and mouse-click
   switching only function through that port per the manual.
3. The physical "Hot key on/off" button must be ON (green Hotkey On LED lit).
4. If the engine appears dead, power-cycle the TH41-3 itself; its own `[R]`
   reset is a hotkey and unusable while the engine is disarmed.

## Known behavior

- Keystrokes pass through cleanly to the focused machine even when the prefix
  is ignored — failed sequences leak their tail into the target console.
- ControlLeft does not work; the manual specifies Right Ctrl only.
- See `../PROBE_NOTES.md` for the full empirical log.
