# TH41-3 switching with kvmctl

## Protocol

Sequential hotkey grammar: **Right Ctrl tapped twice → port number → Enter**. Every key is fully released before the next is pressed; the switch's hotkey engine does not recognize simultaneous chords.

Implemented in `kvmctl/switch.py`:

- `TH41_3` profile (`terived-th41-3`), ports 1–4.
- `plan_switch(profile, port)` validates the port and returns the exact event plan.
- `execute_switch(client, TH41_3, port, dry_run=..., inter_key_delay=..., settle_delay=...)` emits discrete events; `dry_run=True` sends nothing.

### Held-key mode (verified recipe)

Plain taps were filtered by the switch's hotkey detector. The repeatable recipe uses held keys: each key is held down for 120 ms, then released, with a 150 ms gap before the next key. Enable it via `hold_ms` on a profile:

```python
from kvmctl.switch import SwitchProfile, execute_switch

TH41_3_HELD = SwitchProfile(
    name="terived-th41-3-held", min_port=1, max_port=4,
    sequence=(("ControlRight", "tap"), ("ControlRight", "tap"),
              ("Digit{port}", "tap"), ("Enter", "tap")),
    hold_ms=0.120,
    inter_key_delay=0.150,
)
execute_switch(client, TH41_3_HELD, 2)
```

Held-key execution remains strictly sequential—no two keys are ever held at once.

## Full select cycle

`select_machine(client, session, name)` implements the resolved recipe:

1. Optional OTG re-arm: bounce `start_cdrom=true&start_flash=true`, wait 8 s, then disable both and wait 12 s. The USB re-enumeration arms the hotkey engine.
2. Hold `ControlRight` twice, `Digit<N>`, and `Enter`, releasing each before the next event.
3. Settle about 5 s, then verify per policy (`FRAME_CHANGE`, `OCR_IDENTITY`, or `PROMPT_PATTERN`) against the configured machine profile.

The CLI opens an authenticated stream WebSocket before a real re-armed selection and closes it after the operation. Recovery reopens the stream after the OTG bounce and tolerates the expected temporary snapshot 503 before verification.

Selection state is explicit (`UNKNOWN → SELECTED_UNVERIFIED → VERIFIED | VERIFY_FAILED`) on `SessionState`; failures never leave a silently trusted record. An OTG failure raises before any keystrokes are sent.

## Streamer recovery

The OTG bounce can stop ustreamer. `recover_streamer` nudges the encoder through `/api/streamer/set_params?desired_fps=40&quality=80`, retries snapshots, and opens a fresh authenticated `/api/ws?stream=1` connection. The built-in `KvmClient.open_stream()` retains that socket for the synchronous CLI workflow; callers using the lower-level recovery helper may still inject an `open_ws` callable.

```sh
kvmctl --url https://<glkvm-host> --host glkvm.local \
  --user "$KVMCTL_USER" --password "$KVMCTL_PASSWORD" \
  --insecure --yes --transport kvm select pve2
```

## Wiring requirements

1. Comet storage gadget disabled (`start_cdrom=false`, `start_flash=false`) after recovery.
2. Comet USB cable connected to the TH41-3 port marked with the **KEYBOARD** icon.
3. Physical “Hot key on/off” button ON, with the green Hotkey On LED lit.
4. If the engine remains inactive, power-cycle the TH41-3 only when physical intervention is authorized; its own reset is a hotkey and is unavailable while disarmed.

## Known behavior

- Keystrokes pass through to the focused machine even when the prefix is ignored; failed sequences can leak their tail into the target console.
- `ControlLeft` does not work; use `ControlRight`.
- Never use the factory-reset sequence while validating this workflow.
- See [`../PROBE_NOTES.md`](../PROBE_NOTES.md) for the empirical protocol log.
